How a spend is allowed

The cap moves inside the lock.

The cap changes only inside the transaction that locks the funds.

The run

  1. 1. Deploy

    rUSD is minted by anyone. Rova is constructed with that token and a cap of 10.

  2. 2. Fund 30

    fund pulls tokens into the pool. The balance is the float. The cap is the policy.

  3. 3. Naive mode

    Twenty agents call spendNaive for 1. Each call sees unreserved tokens and pays. Spent becomes 20. The vendor receives 20.

  4. 4. Reset

    The owner pulls the leftover tokens and the counters return to zero. The log stays, so the overshoot is still visible.

  5. 5. Reserve

    The pool is funded with 30 again. Twenty agents call tryReserve for 1. Ten lock. Ten emit Refused.

  6. 6. Commit

    Each accepted reservation pays 1 to the vendor. Spent is 10. A commit can pay less than it reserved. The difference stays in the pool.

  7. 7. Expiry

    A reservation has an expiry. After that time anyone can release it, and the views treat it as free so a crashed agent cannot hold the cap.

Calls

fundPull rUSD into the pool.
reserveLock an amount, or revert when the cap has no room.
tryReserveThe same check. On a shortage, emit Refused and return 0.
commitPay the vendor. Leave the unused part of the reservation in the pool.
releaseReturn a reservation to the cap. After expiry, anyone may call it.
spendNaiveThe broken path. It pays unreserved tokens and ignores the cap.
resetZero the counters. A live reservation blocks it.
